LeafID — Design System Audit

Every token and reusable component defined in the codebase, rendered from the real values in Theme.swift and UI/System/ — plus a concrete list of where the app itself doesn't follow its own system.

Source of truth: Theme.swift states it's synced from docs/ui-screens/design_system_build/code.html (the original Tailwind spec). Fonts (Plus Jakarta Sans, Manrope) are referenced by PostScript name with a system-font fallback — no font files are actually bundled in the target, so every screen in the shipped app renders in the system font today, not the intended typeface. This page reproduces that same fallback behavior deliberately, so what you see here is what the app actually renders.

Legacy aliases smell

Six more names in Theme.swift:110–115 point at the same colors above under different names (deepForest→surface, leafGreen→primary, deepGreen→surfaceContainerHigh, leafGreenAlt→primary, slateMuted→onSurfaceVariant, specimenField→surfaceContainerHigh@45%). Harmless today, but two names per color makes future edits error-prone — a future rename of primary has to remember to also catch every leafGreen/leafGreenAlt call site.

Assets & icons

Assets.xcassets contains exactly two entries: AccentColor.colorset (one color, no image sets, no illustration library) and AppIcon.appiconset — whose Contents.json declares a single universal 1024×1024 slot with no image file assigned. There is no icon system: every glyph in the app is a bare Image(systemName:) call (55 call sites, 22 distinct SF Symbols), sized and weighted ad hoc per call site rather than through a shared token — the same visual size (e.g. 18pt / .semibold) is repeated verbatim across LeafPrimaryButton, SecondaryActionButton, and GlassChromeCircleButton instead of being defined once.
