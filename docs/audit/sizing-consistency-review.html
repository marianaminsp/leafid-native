The type scale, as it actually exists

The app has a de facto hero-title scale — 34pt, used deliberately and consistently on Home, Herbarium, Druid, Arboretum, and this session's new Onboarding flow. Two screens break it in opposite directions without a stated reason.

Screen-by-screen

LoginView fixed same session

Title and subtitle both exceeded every other screen's scale — this is why it read as "web, not app"

Fixed

"Welcome Back" was set at 46pt — larger than LeafIDTypography.displayTitle (34pt), the size every other screen in the app treats as its ceiling. The subtitle beneath it was 20pt against the app's standard 16pt body size. Neither number appeared anywhere else in the codebase.

Fixed: title now uses LeafIDFont.boutiqueTitleSize (30pt, matching Paywall's hero scale), subtitle now boutiqueSubtitleSize (16pt). Also trimmed the surrounding vertical rhythm (28pt top padding → 20pt, 12pt internal spacing → 10pt) and the two text fields' vertical padding (16pt → 12pt) — the oversized rhythm was compounding the type-scale issue, not just the type itself.
LeafID_nativeApp.swift:785 (title), :790 (subtitle), AuthTextField/AuthSecureField

The leading arrow on "Login" didn't mean anything

Fixed

Every other primary action button in the app pairs its icon with what the action actually does — "Save to Herbarium" gets a leaf, "Scan another specimen" gets a viewfinder. "Login" had arrow.right, a generic "forward" glyph that didn't describe signing in any more than it described any other button in the app.

Fixed: removed leadingSystemImage: "arrow.right" — the label "Login" already says what it does.
LeafID_nativeApp.swift:825

68pt circular brand mark had no counterpart anywhere else

Fixed

Home, Herbarium, Druid, and Arboretum all open straight into content — no "hero icon in a tinted circle" moment. Login's leaf-in-a-circle was a one-off piece of chrome that didn't recur, reading as imported rather than native to this app's visual language.

Fixed: brought down to 48pt (icon 28pt → 20pt), closer to the Onboarding flow's 52pt fixed leaf mark — quiet, not a hero moment.
LeafID_nativeApp.swift:773-780

Botanical Card one deliberate exception, worth naming as one

Front hero title (44pt) is the other place that beats the 34pt ceiling — but this one's earned

Context

Unlike Login, this is the actual payoff moment of the whole app — the full-bleed photo reveal after a successful scan. Going bigger than the standard hero scale here is a legitimate, deliberate choice a principal designer would sign off on. The problem is it's not recorded as one: it's a bare literal size: 44 with no comment explaining it's an intentional exception, sitting in the same file as a dozen other literals that aren't deliberate.

Fix: name it — a LeafIDTypography.heroCelebration token (or even just a one-line comment) turns "the one place we go bigger" into a documented rule instead of an unlabeled outlier indistinguishable from drift.
Views/Herbarium/BotanicalCardImmersiveView.swift:553

Scan Results dense screen, mostly fine, one real floor violation

"NEW DISCOVERY" badge sat below the app's own label floor

Fixed

Every other eyebrow/label in the app (family names, "COLOUR SIGNATURE", onboarding eyebrows) sits at 10-11pt. This one badge was 9pt — smaller than anything else meant to be read, on a screen that the companion HIG review already flags as having zero Dynamic Type support.

Fixed: brought to 10pt to match the rest of the app's label floor.
Views/Identify/ScanResultsView.swift:438

Otherwise, this screen's smaller title (28pt vs. the 34pt standard) is the right call, not a bug

Working as intended

This is the most content-dense screen in the app — badges, chips, description, two CTAs all competing for the same viewport. Stepping the title down one notch from the 34pt hero scale is a reasonable, proportionate response to that density, not an inconsistency to fix.

Home, Herbarium, Druid, Arboretum, Onboarding clean

All five agree with each other

Clean

Headers on all five consistently use the 34pt/22pt expanded-collapsed pair (or plain 34pt where there's no collapsing header). Body copy is consistently 16pt. Screen-edge horizontal padding is consistently LeafIDTheme.screenHorizontalPadding (24pt) — only two stray literals found in the entire Views/ + UI/System/ tree, both in BotanicalCardImmersiveView.swift, both small/contextual exceptions rather than drift. This is the actual, working baseline the two outlier screens above should be brought back to.

What's actually working — say it plainly, not just the gaps

Corner radius is disciplined

Clean

Nearly everything routes through CornerRadius.card (32) or .immersive (48). Only two bare literal radii found in the whole tree — a 3pt radius on a thin progress-bar element and a 20pt radius on a small avatar-scale image in Druid — both proportionate to elements far smaller than a card, not evidence of a second competing radius system.

Touch targets clear the 44pt floor everywhere checked

Clean

LeafPrimaryButton/SecondaryActionButton both use 16pt vertical padding around their label, landing comfortably above 44pt total height. The floating tab bar's buttons land around 56pt once icon, label, and the bar's own padding are summed. No shortfall found.

The collapsing-header pattern (34→22pt) is now a real, working, shared idiom

Clean

Druid and Herbarium both implement the identical shrink-and-fade behavior on scroll (fixed this session — see git history), and it's the same numbers in both places. Worth formally extracting into one shared component next time either screen is touched, so the idiom can't drift the way LoginView's type scale did.
